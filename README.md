# Календарь сообщества Ersatz Dasein

Публичный календарь и админка: Astro + Vue, Node.js, SQLite.

- `/calendar` — публичный календарь.
- `/admin` — управление событиями, типами, оформлением, доступом и аналитикой.
- Будущий внешний адрес публичной части — https://ersdsgn.club/cal. Настройка выполняется при размещении; админка в `/cal` не входит.

## Развёртывание

Это единственная актуальная версия календаря и админки. Других веток, копий и тестового режима нет — брать код больше неоткуда, искать «демо» не нужно.

Нужны Node.js 24 (см. `.node-version`), доступ сервера к `calendar.google.com` и записываемый диск для SQLite.

```sh
npm ci
npm run build
npm start
```

`npm start` сам загружает `.env`, при первом запуске наполняет базу реальными событиями сообщества из `config/community-calendar.json`, обновляет их из Google iCal и слушает `0.0.0.0:4321` (`HOST`/`PORT` можно переопределить; хостинг обычно задаёт `PORT` сам).

Переменные окружения сервера (можно скопировать `.env.example` в `.env`):

```sh
CALENDAR_ALLOW_REMOTE=1   # админка и её API отвечают по внешнему адресу, а не только с localhost
CALENDAR_ADMIN_OPEN=1     # админка открыта без входа — текущее решение до подключения Telegram
CALENDAR_DATABASE_PATH=/путь/на/постоянном/диске/calendar.sqlite
```

Render: `render.yaml` уже содержит всё нужное (Blueprint). Он описывает бесплатный план без диска: при каждом деплое или перезапуске база создаётся заново из снимка, и настройки админки теряются. Для постоянной работы нужен платный план с диском — см. `docs/deployment.md`.

### Как проверить, что развернулось правильно

1. В журнале запуска есть сводка «Календарь сообщества запущен»: версия `2026-11-25-without-demo`, событий больше нуля, синхронизация `connected`, админка «открыта без входа».
2. `/calendar` показывает события сообщества (например, «Техножрецы», «Секвенсоры»), справа вверху кнопка «Войти через Telegram».
3. `/admin` открывается, в нём те же события и встроенное превью календаря.

Если событий нет, синхронизация не `connected` или админка отвечает 401/403 — это настройки окружения или сети, а не ошибка кода. Код не менять: свериться со сводкой запуска и переменными выше.

Не делать:
- не запускать `node dist/server/entry.mjs` напрямую — так база не наполняется событиями сообщества;
- не запускать `scripts/seed.mjs` на рабочей базе — это синтетический набор только для автотестов;
- не возвращать демо-режим, демо-вход и тестовые события — они удалены намеренно.

## Быстрый локальный запуск

Нужны Node.js 24 и npm. Все команды выполняются из корня репозитория.

```sh
npm ci
npm run build
npm run preview:community
```

Запускаются календарь и админка с реальными событиями сообщества: первоначальный снимок из `config/community-calendar.json` и обновление из Google iCal (при недоступности Google сохраняется снимок). Календарь: http://127.0.0.1:4390/calendar. Админка: ссылка входа выводится при запуске. Используется отдельная база в `artifacts/telegram-review/`; рабочие базы не изменяются. Остановка — Ctrl+C.

Тестового режима и демонстрационных событий в приложении нет. Синтетический набор `scripts/seed.mjs` используется только автотестами на их собственных базах.

```sh
npm run build
npm run typecheck
npm test
npm run test:admin
```

Браузерные проверки используют установленный Google Chrome. Тесты работают с отдельными базами в `artifacts/`.

Расширенная проверка Firefox/WebKit, отказов сети, галереи и резервных копий: [docs/testing.md](docs/testing.md). Физические iOS/Android, системная клавиатура и реальная Telegram-авторизация требуют отдельной проверки принимающей команды.

## Границы реализации

Календарь и админка используют общие серверные данные; поддерживаются повторы, оформление и импорт Google/Яндекс по iCal. Чтение из Google — по iCal. Запись в Google (необязательно): если задан ключ сервисного аккаунта (GOOGLE_SERVICE_ACCOUNT_FILE) и админка закрыта, название, описание, ссылка, дата и время событий из Google сохраняются из админки прямо в Google Календарь; без ключа или при открытой админке эти поля, как и раньше, меняются только в самом Google. Настройка — docs/deployment.md, раздел «Запись в Google».

Настоящая Telegram-авторизация и получение членства/градусов подключаются принимающей командой. Текущий вход по секретной ссылке — временный адаптер. Открытая админка (`CALENDAR_ADMIN_OPEN=1`) не обеспечивает рабочую авторизацию. Для сохранения настроек нужны постоянный диск с SQLite и резервное копирование.

`render.yaml` и `scripts/render-start.mjs` запускают действующий стенд: реальные события сообщества, админка открыта без входа (`CALENDAR_ADMIN_OPEN=1`) до подключения Telegram. Размещение и закрытие админки описаны в `docs/deployment.md`.

В Git входят исходники, миграции, lock-файл, локальные шрифты/графика, согласованный начальный снимок и проверки. `.env`, базы, резервные копии, зависимости, сборки и отчёты исключены. История этапов разработки доступна в Git; старые отчёты и переписки убраны из текущего комплекта.
