# Календарь сообщества Ersatz Dasein

Публичный календарь и админка: Astro + Vue, Node.js, SQLite.

- `/calendar` — публичный календарь.
- `/admin` — управление событиями, типами, оформлением, доступом и аналитикой.
- Будущий внешний адрес публичной части — https://ersdsgn.club/cal. Настройка выполняется при размещении; админка в `/cal` не входит.

## Быстрый локальный запуск

Нужны Node.js 24 и npm. Все команды выполняются из корня репозитория.

```sh
npm ci
npm run build
npm run demo
```

Запуск создаёт отдельную локальную базу с тестовыми данными и печатает временную ссылку входа в админку. Публичная страница: http://127.0.0.1:4321/calendar. Остановка — Ctrl+C. `demo` не предназначен для рабочего сервера.

Для локального просмотра согласованных событий сообщества вместо тестового набора:

```sh
npm run preview:community
```

Календарь: http://127.0.0.1:4390/calendar; ссылка входа в админку выводится при запуске. Используется отдельная база в `artifacts/telegram-review/`, первоначальный снимок из `config/community-calendar.json` и обновление Google iCal. При недоступности Google сохраняется снимок. Рабочие базы не изменяются.

## Проверка

```sh
npm run build
npm run typecheck
npm test
npm run test:admin
```

Браузерные проверки используют установленный Google Chrome. Тесты работают с отдельными базами в `artifacts/`.

Расширенная проверка Firefox/WebKit, отказов сети, галереи и резервных копий: [docs/testing.md](docs/testing.md). Физические iOS/Android, системная клавиатура и реальная Telegram-авторизация требуют отдельной проверки принимающей команды.

## Границы реализации

Календарь и админка используют общие серверные данные; поддерживаются повторы, оформление и импорт Google/Яндекс по iCal. Импорт односторонний: расписание внешнего события меняется у источника, оформление и доступ — в админке.

Настоящая Telegram-авторизация и получение членства/градусов подключаются принимающей командой. Текущий вход по секретной ссылке — временный адаптер. Открытый режим демонстрации не обеспечивает рабочую авторизацию. Для сохранения настроек нужны постоянный диск с SQLite и резервное копирование.

`render.yaml` и `scripts/render-start.mjs` сохранены для действующего демонстрационного стенда. Рабочее размещение описано в `docs/deployment.md`.

В Git входят исходники, миграции, lock-файл, локальные шрифты/графика, согласованный начальный снимок и проверки. `.env`, базы, резервные копии, зависимости, сборки и отчёты исключены. История этапов разработки доступна в Git; старые отчёты и переписки убраны из текущего комплекта.
