# Правила разработки

Прочитать README.md, docs/architecture.md, docs/deployment.md и INTEGRATION.md. Перед правками проверить ветку, рабочее дерево и origin/main. Не включать чужие незавершённые изменения в коммит.

## Поведение

- Календарь и админка читают общие серверные данные. Не подменять их тестовым набором.
- Все события видимы; права ограничивают переход к участию. Проверять доступ также в API и ICS.
- Точные наборы градусов/лож выпуска могут уточнять правила типа. Не выводить принадлежность по названию; назначения источника находятся в config/community-calendar.json.
- Google/Яндекс подключаются по iCal. Расписание внешнего события меняется у источника; приложение хранит оформление, доступ и настройки выпусков. Обратная запись в Google не реализована.
- Идентичность импорта: источник + UID/RECURRENCE-ID. Синхронизация сохраняет внутренние настройки и исключения.
- Секретная ссылка и демо не являются настоящей Telegram-авторизацией. Не расширять публичные API без проверки доступа.
- Будущий /cal относится только к публичному календарю. Адрес админки этим решением не определяется.

## Код и данные

- Node.js 24, Astro/Vue, SQLite/Drizzle. Не добавлять зависимости без необходимости и согласования.
- Миграция: SQL в drizzle/, список в src/lib/db/index.ts, счётчик в scripts/verify.mjs.
- Тесты только на отдельных базах. Не запускать seed поверх рабочей базы.
- Не коммитить .env, токены, SQLite, backups/, artifacts/, node_modules/ и dist/.
- Не переписывать историю Git ради обычной уборки.

## Интерфейс

- Сохранять интерфейс и поведение, если задача не требует их менять.
- Токены: design/tokens.json. tokens.css и admin-lino-kit.css генерируются перед сборкой; не править вручную.
- lino-ui 0.2.0: перед UI-работой прочитать node_modules/lino-ui/AGENTS.md. Проектные кнопки и ButtonGroup имеют собственное оформление.
- Для нового макета нужны актуальная Figma-ссылка и доступ либо явное разрешение работать по экспортам/скриншотам. Старые номера фреймов не являются заданием.
- Сохранять исходные подтверждённые SVG и PNG.

## Проверки

Перед передачей: npm run build, npm run typecheck, npm test. После правок админки: npm run test:admin. Сценарии — docs/testing.md. Указывать фактически выполненные проверки; эмуляция touch не заменяет телефон.
